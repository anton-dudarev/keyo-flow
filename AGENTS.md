# AGENTS.md — Keyo

## 1. О проекте

**Keyo** — кроссплатформенная утилита для записи, редактирования и воспроизведения действий пользователя (мышь и клавиатура).
Базовый функционал (MVP):

- Перехват глобальных событий ввода (движение, клики, скролл, нажатия/отпускания клавиш).
- Сохранение и загрузка сценариев (макросов) в формате JSON или RON.
- Воспроизведение сценариев с настройкой скорости и количества повторов.
- Глобальные горячие клавиши для старта/остановки записи и аварийного прерывания (Kill-Switch).
- Графический интерфейс для управления сценариями и настройками.

## 2. Стек и команды

- **Язык / Фреймворк:** Rust (edition 2021).
  - *Эмуляция и перехват:* `rdev` (перехват хуков) + `enigo` (эмуляция ввода).
  - *Графический интерфейс (GUI):* `egui` (с бэкендом `eframe`).
  - *Сериализация:* `serde`, `serde_json`.
- **Сборка:** `cargo check` (разработка) / `cargo build --release` (релиз).
- **Запуск тестов:** `cargo test --lib` (запускать только модульные тесты, изолированные от реальной ОС).
- **Линтер / Форматтер:** `cargo clippy --all-targets -- -D warnings && cargo fmt --check` (код с ворнингами Clippy считается невалидным).

## 3. Архитектура проекта

Логика строго разделена на независимые слои, общающиеся через `mpsc::channel`:

- `src/platform/` — низкоуровневые обертки над хуками ОС и эмуляцией.
- `src/core/recorder.rs` — расчет относительных задержек, фильтрация шума, генерация событий.
- `src/core/player.rs` — движок воспроизведения в отдельном потоке. Должен использовать точные `std::time::Instant` для компенсации дрейфа таймингов.
- `src/core/safety.rs` — логика Kill-Switch и функция `release_all_modifiers()` для сброса состояния клавиш.
- `src/storage/` — сериализация/десериализация сценариев.
- `src/ui/` — окна и виджеты на базе `egui`. UI-поток **не должен** блокироваться логикой записи или воспроизведения.

## 4. Критические правила для ИИ-агента (Guardrails)

1. **Разделение потоков (Threading):** `eframe` (egui) требует запуска в главном потоке. Логика перехвата ввода (глобальные хуки `rdev`) и цикл воспроизведения (`player`) ОБЯЗАНЫ запускаться в отдельных `std::thread` и обмениваться сообщениями с UI через неблокирующие каналы (`std::sync::mpsc` или `crossbeam_channel`).
2. **Запрет на реальный ввод в тестах:** Никогда не используй реальные вызовы эмуляции или хуков в тестах. Логика расчета времени и координат должна тестироваться на моках (чистых функциях).
3. **Гарантированный сброс клавиш:** Любой цикл воспроизведения должен реализовывать паттерн Drop или аналог `try-finally`, который принудительно отжимает модификаторы (`Ctrl`, `Shift`, `Alt`, `Meta`) в случае прерывания (Kill-Switch) или ошибки.
4. **Изоляция Kill-Switch:** Обработка экстренной остановки (например, `Esc`) должна прерывать поток воспроизведения мгновенно, минуя ожидание (`sleep`). Используй атомарные флаги (`Arc<AtomicBool>`).
5. **Точность таймингов:** Использовать только `Instant::now()` для замеров времени. Никогда не использовать системное время (`SystemTime`) для расчета задержек (`duration`), так как оно подвержено сдвигам (NTP).
6. **Координаты:** При работе с координатами мыши учитывать, что `enigo` работает с абсолютными пикселями, а в `egui` могут быть логические пиксели (с учетом DPI монитора).

## 5. Версии и релизы

- Версия приложения задаётся в `Cargo.toml` как `MAJOR.MINOR.PATCH`. Версия JSON-формата сценариев управляется отдельно.
- До `1.0.0` исправления повышают `PATCH`, а новые возможности и несовместимые изменения повышают `MINOR` со сбросом `PATCH` в ноль. Выпускай `1.0.0`, когда проект готов заявить стабильную совместимость. Начиная с `1.0.0`, несовместимые изменения повышают `MAJOR`, совместимые новые возможности повышают `MINOR`, а совместимые исправления повышают `PATCH`. При повышении разряда сбрасывай младшие разряды в ноль.
- Добавляй заметные пользователям изменения в раздел `Unreleased` файла [CHANGELOG.md](CHANGELOG.md).

Порядок выпуска:

1. Обнови версию в `Cargo.toml`, запусти `cargo check` для обновления `Cargo.lock` и проверь, что версия пакета в обоих файлах совпадает.
2. Перенеси записи из `Unreleased` в раздел новой версии с датой выпуска. Оставь пустой раздел `Unreleased` наверху.
3. Запусти `cargo test --lib`, `cargo clippy --all-targets -- -D warnings` и `cargo fmt --check`.
4. После успешных проверок закоммить файлы релиза и поставь на этот коммит аннотированный тег командой `git tag -a vX.Y.Z -m "Release vX.Y.Z"`, подставив версию из `Cargo.toml`.
